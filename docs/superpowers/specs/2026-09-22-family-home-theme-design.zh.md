# 家人小屋主题插件设计

[English](2026-09-22-family-home-theme-design.md) | 中文

## 概述

本设计定义一套温馨家庭风格的 DSH 皮肤，支持自定义名字、欢迎语、三套配色和一张服务器共享的家庭封面照片。视觉方向已获确认，正式实现尚未开始。皮肤保留现有模型行为、鉴权和成员共享权限。浏览器本地外观偏好与邀请码部署中的共享封面和会话相互独立。

<a id="appearance"></a>
## 范围与外观

默认名称为“家人小屋”，欢迎语为“回来啦，先歇一会儿。”纸质相框和小屋爱心标识构成皮肤识别元素。现有会话和工作区保留真实名称与操作；预览里的示例会话不会写入正式环境。

| 区域 | 呈现要求 |
|---|---|
| 侧栏 | 小屋标识、可配置家庭名称、暖色导航和新对话按钮 |
| 浏览器标签页 | 家庭名称；选中会话时保留 `conversation title — family name` 格式 |
| 空白对话页 | 可配置欢迎语、家庭相框和可选的家庭主题起始提示词 |
| 输入框与消息 | 暖色按钮、可读的消息背景，以及全部原有发送、停止、上传和模型控件 |
| 邀请页 | 家庭名称、小屋标识、“欢迎回家。”，以及使用“进来坐坐”按钮文案的原有邀请表单 |
| 设置 | “小屋外观设置”入口、配色选择、名字与欢迎语、照片替换与移除，以及启停开关 |

三套已确认配色均可选择。晨光奶油作为初始默认值，浏览器已保存的选择优先。整体采用纸张色调、清晰文字、圆润控件与克制动效。错误、警告、审批和禁用状态必须保持可辨识。

| 配色 | 底色 | 强调色 | 主要文字 | 辅助文字 | 按钮文字 |
|---|---|---|---|---|---|
| 晨光奶油 | `#FFF9F1` | `#AC492B` | `#4E382C` | `#705F53` | `#FFFDF8` |
| 花园午后 | `#F7F8EF` | `#46654C` | `#344738` | `#5C6859` | `#FFFDF8` |
| 晚灯时光 | `#29231F` | `#F0AE7C` | `#F8E8D3` | `#D0BFA9` | `#392A20` |

标题采用系统楷体与衬线字体回退，形成手写感；控件和对话正文采用系统中文无衬线字体。插件不请求第三方字体或背景媒体，共享封面从经过鉴权的同源服务器获取。正文遵循 DSH 的字号设置。普通文字对比度目标不低于 4.5:1；装饰不得阻挡操作或遮挡内容。

已确认的效果稿包括[晨光奶油](assets/family-home-theme/morning.png)、[花园午后](assets/family-home-theme/garden.png)、[晚灯时光](assets/family-home-theme/evening.png)、[手机布局](assets/family-home-theme/mobile.png)和[邀请页](assets/family-home-theme/login.png)。这些是设计依据，不是正式插件已经实现的截图。

<a id="customization"></a>
## 定制与照片

名字、欢迎语、配色和启停状态属于当前浏览器配置及站点来源，普通刷新与浏览器重启后保留，但不跨设备同步。唯一的家庭封面保存在服务器，供所有已通过邀请码鉴权的成员共享；清除某个浏览器的数据不会删除它。插件不会把封面发送给 Kimi、加入模型提示词或写入会话事件。

- 名字默认“家人小屋”，最多 16 个 Unicode 字符；欢迎语最多 32 个。空字段显示默认值。用户文字只能作为文本渲染，不得作为 HTML。
- 文件选择器和拖放区域接收一张 JPG、PNG 或 WebP。建议的可部署配置默认值为：输入 10 MiB、解码后 2400 万像素、输出长边 1600 像素。
- 服务器校验声明类型、实际可解码性、流式字节大小和尺寸；浏览器检查只提供提前反馈。缩放并重新编码为 WebP，不保留原始上传文件及元数据。处理并发数通过已验证的配置限制。
- 不可变的规范化图片及带版本的当前封面记录，存放在 Harness home 下的插件专属目录，不进入 release 目录，并纳入数据备份。个人小型外观偏好保存在浏览器中，不复用会话附件作为共享封面存储。
- 只有校验与持久存储均成功后，才原子发布封面记录。无效文件、上传中断、服务器空间不足和处理失败保留旧封面。修改必须携带已观察的封面版本；并发发生陈旧替换或移除时返回冲突，请成员刷新，不覆盖较新的选择。
- 所有已通过邀请码鉴权的成员，均可按现有共享权限替换或移除封面。确认移除后，所有人恢复为插画，并且只清理插件拥有的图片数据。停用皮肤、移除插件包或清除个人偏好均不删除共享封面；清理不得影响 DSH 附件或其他文件。

上传者立即看到已提交的封面；其他成员在页面加载、刷新、窗口重新获得焦点和重连时获取最新版本，首版不包含持续实时推送。私有的鉴权读取、上传和移除路由执行授权及同源写操作检查，不把封面放在公开静态目录或公开邀请路由前缀下。HTTP 响应采用禁止缓存的私有策略，失去登录授权时清除已渲染封面。原始文件名不得决定服务器路径。

修改家庭名字会更新侧栏、浏览器标题与登录页标题。邀请页可在登录前应用同一份有长度限制的浏览器本地文字和配色，但不得请求或展示共享封面。新浏览器显示配置中的默认名称与配色，登录后显示家庭当前照片。“共享”指受邀群体，不是向互联网公开，也不新增个人隔离。

起始卡片只在点击时填入真实输入框，不自动发送。卡片位置与文案属于呈现；用户发送草稿后，沿用正常的 DSH 记录和模型投递流程。正式应用不包含模拟回复、虚假会话或装饰性数据。

<a id="integration"></a>
## 插件集成

实现面向项目当前 Web 组合，以可选的 Cordis 组合包分发。停用后移除其呈现效果并恢复原生界面，同时保留已存偏好和共享封面以便重新启用。清除个人定制与移除共享封面是不同操作；共享移除需要明确说明会影响所有人的二次确认。安装与生产启用是两个分开的操作。

<details>
<summary>实现约束</summary>

使用[主题注册](../../../packages/client/ui-theme/README.zh.md)、已有侧栏品牌 slot、对话组件 slot 和设置扩展。[侧栏 slot 声明](../../../packages/client/ui-sidebar/src/client/contract/slots.ts)已经提供标识与名称替换。[文档标题所有者](../../../packages/client/ui-layout/src/client/DocumentTitle.tsx)目前使用构建或本地化产品名，需要一个小型类型化品牌扩展，继续由它统一负责 `document.title`。首页文案、照片布局和邀请页呈现同样在现有 slot 不足时增加明确的所有者管理扩展点。

不得通过轮询或改写已渲染 DOM 文本、匹配哈希 CSS 类名、替换完整宿主包或修改 agent loop（智能体循环）实现品牌定制。配色与浏览器本地定制放在家庭插件中，默认行为与扩展点所有权保留在已有 UI 包中。公共注册返回 disposer，并通过 Cordis effect 安装。插件移除和部分初始化失败必须恢复原生呈现，不残留处理器或产生多个标题写入方。

[invite-auth 插件](../../../packages/host/invite-auth/README.zh.md)继续负责验证、Cookie、来源校验、限流、重定向和失败状态。外观扩展可以提供可信呈现数据及固定的本地偏好启动脚本，不得替换鉴权处理器。若登录前需要脚本，使用每次响应生成的 nonce 与转义数据，不使用 `unsafe-inline`、`unsafe-eval`、远程脚本或用户提供的 CSS/JavaScript。卸载外观提供方恢复默认登录表单，不撤销鉴权路由。

家庭插件负责 Host 封面存储及经过鉴权的上传、读取和移除方法。复用维护中的图片处理依赖及现有 Connection/Remote 鉴权机制，提供流式上传限制、带版本校验的更新、有界处理及取消或卸载时的清理。不得执行上传内容或接受任意服务器路径。只有启用皮肤的已登录客户端请求时，才需要加载元数据和图片字节。

运行限制、封面存储目录、默认名称、欢迎语、配色和起始卡片开关均属于经过校验的 Cordis 配置。读取时校验浏览器存储值和服务器持久元数据。产品文案使用类型化中英文本地化字典。内置插画与小屋标识使用项目自有素材。

同一时刻只允许一套皮肤持有这些呈现覆盖。检测已声明的主题或品牌冲突，保留原生界面并给出明确诊断，不静默叠加皮肤。不得删除已部署的 `dsh-theme` 包；未来切换时保留其配置，先明确停用冲突的呈现，再启用本皮肤。仅凭包名无法证明未知第三方 CSS 没有冲突。

</details>

本插件不新增家庭账户、个人权限、多照片相册、合同处理或模型凭据。封面上传是独立外观功能，不改变文档或消息附件。现有实例仍由可信邀请码持有人共享。不启用本组合包的其他 profile 与安装保持不变。

<a id="verification"></a>
## 验证与交付

独立预览已验证名字与欢迎语编辑、三种配色、本地图片替换与刷新、无效文件拒绝、登录样式、模拟对话控件及手机导航。浏览器检查未发现脚本错误、失败 HTTP 请求、外部请求或手机横向溢出。此本地预览尚未实现服务器共享；正式集成还需要以下证据。

1. 单元测试覆盖配置与存储偏好解析、服务器权威图片校验、版本冲突、写入中断、存储失败、自有文件清理及启停恢复。
2. 真实 Loader 测试覆盖呈现注册与移除、可选提供方缺失、明确冲突和鉴权行为不变；拒绝未登录的封面读写、跨源写入、路径注入、恶意自定义文字和脚本注入，并验证合法请求成功。
3. 真实 Web 浏览器测试使用相互独立的已登录上下文：一方上传，另一方刷新或回到窗口后看到共享封面；移除、重连和服务器重启保持约定状态。同时覆盖桌面和手机配色、标题导航、不把照片发送给模型、登录前不请求照片、键盘焦点、减少动态效果和恢复原生界面。验证实际文字对比度，不只检查命名配色值。
4. 无密钥的录制会话场景在皮肤下验证真实输入框、流式回复、刷新及 transcript（文本记录）不变。鉴权页和纯外观的预期输出留在各自所有者的测试中。
5. 构建、相关类型与 lint 及包检查、双语文档检查和一次构建后 profile 冒烟测试覆盖可安装组合包。部署另需备份、现有主题冲突检查及真实 Kimi/浏览器验证；确认本设计不代表部署。
