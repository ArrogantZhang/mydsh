# Agent Note: 私密共享家庭封面与本地外观

Status: implemented

[English](2026-09-22-family-cover-and-personal-appearance.md) | 中文

## 问题

共享家庭封面需要在切换浏览器和替换发布版本后仍然存在，同时不能变成公共资源或模型附件。个人品牌设置不能改变其他访问者的偏好，也不能替换正在使用的输入框。多位已授权访问者可能修改同一张封面。

## 决策

Host 独占的目录存储一张处理后的封面及带版本的元数据指针。Connection 对全部读取和修改进行鉴权；现有的[邀请码权限](2026-08-24-invite-code-web-authentication.zh.md)保持不变。写锁和版本比较会拒绝基于旧版本的修改。替换准备完成之前保留原指针；读取时验证所引用内容的摘要。修改响应失败后客户端仍会刷新，因为发布可能已经提交。

浏览器本地外观使用拥有方声明的品牌、标题和首页 slot。`theme.present()` 临时应用已注册的调色板而不写入 Host 偏好；dispose（资源释放）后显示最新的底层选择。[样式约束](../process/2026-07-19-web-styling-system.zh.md)继续约束组件。邀请码页面拥有方保留真实表单和鉴权策略，转义文本，并仅通过每次响应生成的 nonce 授权受信任的固定启动脚本。

## 考虑过的替代方案

**把照片存入 localStorage。** 这无法在独立浏览器之间共享封面，也无法保留由服务器管理的备份。因此本地存储只保存外观。

**提供公共图片 URL。** 这会在未经邀请码授权时泄露家庭照片。因此所有图片读取都经过 Connection 的鉴权通道。

**替换外壳 DOM 或共享主题设置。** 修改 DOM 会绕过组件所有权，共享偏好则会改变其他访问者的界面。由拥有方管理的 slot 和临时调色板选择保留了生命周期和个人作用范围。

## 影响

所有获准访问者拥有相同的封面编辑权限；这不是多租户权限模型。读取会在启用、获得焦点、重新连接和修改后刷新，而不是使用持续推送流。资源预算属于经过校验的配置，dispose 会等待已启动工作完全停稳。源码测试覆盖版本冲突和取消，真实 Web 测试覆盖跨浏览器共享和重启，借用的会话记录用于验证原有输入框路径。
